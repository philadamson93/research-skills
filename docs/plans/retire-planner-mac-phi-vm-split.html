TL;DR. Phil's Stanford Claude Code for Education account is now high-risk-data compliant on both his Mac and his VMs, so the old "planner Mac has no PHI clearance, VM does" split no longer holds. This plan retires that split across one shared repo (research-skills) plus five downstream repos: code execution + /phi-vet discipline replace the Mac's hard no-execution/no-SSH-into-VM rules, GPU/throughput work still stays on the VM fleet (a capacity reason, not a compliance one), and a Mac-side GCS bucket mount replaces git commits as the cross-machine sync mechanism. rad-eval's own Vertex-only BAA gate for dispatched LLM sessions is explicitly untouched; its separate machine-posture table is not.

Gotchas

The two research-skills "clones" are actually one symlink

RadAWS/code/research-skills is a symlink to VISTA/code/research-skills — confirmed via readlink/realpath during review, correcting the plan's first draft. Every research-skills edit is a single edit, visible to both trees the instant it lands. No git pull sync step exists or is needed.

Phase 2's step order is load-bearing, not cosmetic

Wiring the hook before removing the allowlist entry is a safe no-op (the hook stays inert while the Mac is still allowlisted). Reversing the order opens a real window where the Mac is ASSUME_PHI with zero mechanical commit gate.

settings.json and CLAUDE.vm.md have no landing ceremony

~/.claude/settings.json isn't version-controlled at all — the hook-wiring edit takes effect on save. VISTA/code/CLAUDE.vm.md lives in a directory that isn't a git repo, so editing it here doesn't get it onto the actual VM — Phil copies it over by hand.

research-skills has no docs/plans/README.md

Found during review: this repo tracks plan status via each doc's own Status: header, not a tracked-plans table. This plan's "Files to Modify" originally (wrongly) assumed one existed — fixed.
