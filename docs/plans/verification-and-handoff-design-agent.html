Knobs & contracts

Complexity classifier (both touchpoints share it)

simple  = one handoff, one repo, no decision gates,
          no banked prior-SHA, no destructive write
complex = ANY of { cross-repo SHA ripple, more than one handoff phase,
          class-2 decision gates, bank / un-bank logic,
          destructive or irreversible writes, multi-target bundling }

simple  -> generative: inline guidance   · audit: distinct section in the one chosen reviewer's pass
complex -> generative: spawn subagent     · audit: separate focused reviewer invocation

Handoff phasing schema (new 5th bullet in claude_ops.md's Verification & VM handoff template)

Compact per-phase schema (not free prose) so /plan-handoff-readiness can check its fields. Required for complex-tier plans; a simple single-phase handoff states its one phase inline.

Phase N — <name>
  · purpose
  · banked-from-prior   (which steps / SHA carry forward, do NOT re-run)
  · gates               (class-2 forks the executor resolves inline)
  · destructive?        (irreversible write — STOP before it)
  · stop / deviation routing
  · next-doc trigger

Acceptance rule (checkable)

The command docs (review-plan.md, vm-handoff.md, plan-handoff-readiness.md) may contain only invocation / ownership / mechanics text plus a link. The archetype menu, the envelope, and the batching discipline live only in the canonical spec; repo-specific recipes live only in the per-repo checklist. Enforced by a rg readback in the verification pass.

Gotchas

Lens duplication is the failure mode if Step 2 is skipped
The plan preaches "point at canonical, don't duplicate," but review-plan.md already owns the archetype/behavioral content inline. If the migration is skipped, you stand up a second review surface owning the same archetypes with subtly different wording — the exact drift the plan exists to prevent. The rg readback is the teeth.
claude_ops.md edits ripple to every repo (symlink)
Every VISTA repo's docs/claude_ops.md is a symlink to research-skills/claude_ops.md. The Handoff phasing bullet is a change to the shared operating standard — blast radius is all ~50 repos. Keep the addition backward-compatible (a new optional bullet), and verify the symlink still resolves.
Auto-run is intended — and fine, because /review-plan is basically always run
The audit pass "auto-runs" only as a component of a review the user already opted into — the outer /review-plan is still offered, never auto-invoked. And since /review-plan is run on essentially every non-trivial plan, auto-running the verification component is a feature, not a loss of control (resolved 2026-07-08). The complex-tier separate reviewer invocation is authorized by the same initial reviewer choice and runs silent (OQ1 resolved).
Don't double-own vm-handoff's operational mechanics
The canonical spec owns plan-time strategy selection only. Rendering, the tiered sign-off gate, Expected/Stop enforcement, the class-1/2/3 deviation taxonomy, and supersede mechanics stay owned by vm-handoff.md — the spec points at them rather than restating them.
